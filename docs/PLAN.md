## 2. Аудит Pixel Agents (основа)

Репозиторий: `pixel-agents-hq/pixel-agents` (ранее `pablodelucca/…`), MIT, v1.5.0, ~10k ★, активная разработка (последний push 03.11.2026).

**Архитектура (строгие слои):**

- `core/` — контракты без побочных эффектов: AsyncAPI 3.0 (`asyncapi.yaml` → сгенерированные `messages.ts`), `HookProvider`, `AgentEvent`, `TeamProvider`, `MessageTransport`, `TerminalAdapter`.
- `server/` — Fastify 5 + WebSocket: `AgentRuntime`, `agentStateStore` (EventEmitter, единый источник истины), `sessionRouter` (session_id → agent, буферизация, внешние сессии), `hookEventHandler`, `fileWatcher` (fs.watch + polling 500 мс, построчный буфер JSONL, детект `/clear`), `transcriptParser`, `timerManager` (permission/waiting), persistence в `~/.pixel-agents/` (атомарная запись), standalone CLI.
- `providers/hook/claude/` — единственное место, знающее Claude: нормализация 11 hook-событий, consent-gated установщик hooks (бэкап, верификация, откат), чтение команд `~/.claude/teams/`.
- `webview-ui/` — React 19 + Vite + **Canvas 2D**: rAF-цикл с ограничением дельты, z-sort рендер, BFS-pathfinding по тайлам, FSM персонажа (idle/walk/type + wander), сидения, сабагенты рядом с родителем, matrix-эффект появления, редактор офиса (пол/стены/мебель/ковры/зоны/питомцы, undo/redo, import/export JSON, до 64×64), загрузка внешних asset-паков по manifest.
- Терминал standalone: серверный PTY (`@lydell/node-pty`) + xterm, доступ только с токеном; встроенный mobile shell.
- Тесты: Vitest (28 файлов server), Node test runner, Playwright e2e с `mock-claude`.

**Что отлично подходит нам:** event-пайплайн, обнаружение внешних сессий, сабагенты/команды, consent-модель hooks, токен-разделение «наблюдение / управление», редактор, Canvas-движок, тесты.

**Что нужно менять/добавлять:**

1. `AgentEvent` не несёт `source`, `timestamp`, `parentAgentId`, `confidence`, ключа дедупликации → расширяем (см. §5).
2. Состояний мало (typing/reading/idle/waiting) → нужна расширенная модель статусов и «свободное время».
3. Провайдеры только hook-типа; transcript-only провайдер (нужен для Codex) авторами явно отложен «до реального второго провайдера» — мы его и сделаем.
4. Истории событий как продукта нет (persist — в основном layout/конфиг) → добавить журнал + Replay.
5. Визуал — светлый офис; нужен новый арт-пак и слой освещения (ночь, лампы, неон).
6. VS Code-адаптер нам не нужен, но удалять его невыгодно (конфликты при синхронизации с upstream) — оставляем, не развиваем.

**Лицензии Pixel Agents:**

- Код — MIT (© 2026 Pablo De Lucca) → сохраняем `LICENSE`, добавляем `NOTICE.md`.
- Мебель/пол/стены — после PR #117 заявлены как open-source замена прежнего проприетарного тайлсета, но **конкретная лицензия каждого файла в репозитории не указана** → проверить по истории PR перед публичным релизом.
- Персонажи — основаны на паке JIK-A-4 «Metro City» (itch.io), лицензия стороннего автора → для своего продукта **заменяем на оригинальных персонажей**; до замены — только локально, с указанием авторства.

## 5. Модель событий

Расширяем `AgentEvent` Pixel Agents оболочкой (обратно совместимо):

```ts
interface ObservedEvent {
  id: string; // стабильный ключ дедупликации
  source: 'claude-code' | 'codex' | string;
  channel: 'hook' | 'transcript' | 'replay' | 'demo';
  sessionId: string;
  agentId: string; // главный агент = сессия; сабагент = agent_id / tool_use_id
  parentAgentId?: string;
  kind:
    | AgentEvent['kind']
    | 'promptSubmit'
    | 'toolFailure'
    | 'compactStart'
    | 'compactEnd'
    | 'rateLimited'
    | 'error'
    | 'taskCreated'
    | 'taskCompleted';
  ts: number; // время события из источника; fallback — время приёма
  confidence: 'confirmed' | 'inferred'; // hook = confirmed; эвристика JSONL = inferred
  task?: string; // только если пришло из источника (prompt, description субагента)
  tool?: { id: string; name: string; summary?: string }; // summary — замаскированный
  data?: Record<string, unknown>; // доп. поля, после фильтра секретов
}
```

- **Дедупликация:** `id = source:sessionId:(tool_use_id|uuid|turn_id):kind`. Hook и транскрипт описывают одно событие → побеждает первое, второе дополняет поля. LRU-набор ключей + сохранение в журнале.
- **Восстановление:** клиент WS получает снапшот состояния + `lastEventId`; при переподключении — дельта с журнала. Сервер при старте восстанавливает состояние из журнала + перечитывает хвосты активных транскриптов.

**Статусы агента (только по реальным событиям):**

| Статус                                                                       | Откуда                                               | Поведение персонажа                    |
| ---------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------- |
| `working:*` (writing/reading/searching/running/browsing/delegating/thinking) | PreToolUse, tool_use в транскрипте, UserPromptSubmit | на рабочем месте / в профильной зоне   |
| `waiting_permission`                                                         | PermissionRequest, Notification(permission_prompt)   | у стола, «✋» + звук                   |
| `waiting_user`                                                               | Notification(idle_prompt)                            | **свободное время** + метка «ждёт вас» |
| `idle` (ход завершён)                                                        | Stop / task_complete                                 | **свободное время**                    |
| `compacting`                                                                 | PreCompact/PostCompact                               | анимация у шредера                     |
| `error` / `rate_limited`                                                     | PostToolUseFailure, StopFailure                      | индикатор над головой                  |
| `ended`                                                                      | SessionEnd или нет активности > N мин и файл закрыт  | уходит из офиса → архив                |
| `disconnected`                                                               | источник замолчал во время работы                    | «полупрозрачный», метка                |
| `unknown`                                                                    | нет данных                                           | явная подпись `Unknown`                |

Правило честности: игровая активность (кофе, диван, разговоры) **разрешена только в `idle`/`waiting_user`**, в UI всегда подпись реального статуса; поля без данных — `Unknown`/`Unavailable`.

## 7. Игровой мир и поведение

- Остаёмся на **Canvas 2D** Pixel Agents: тайлы, BFS-pathfinding, коллизии по walkability-карте (мебель непроходима), назначение мест, z-sort.
- **Зоны офиса** (через «Areas» редактора): рабочие столы, библиотека (reading/search), серверная (Bash), окно-обсерватория (web), переговорка (делегирование/сабагенты), кухня + кофемашина, лаундж с диванами, вход.
- **Иерархический FSM персонажа:** верхний уровень = реальный статус агента; нижний уровень = «досуг» (только в idle/waiting_user): `goCoffee → drink → wander → sofa → window → chat(с соседом, тоже свободным) → returnDesk`. Веса, кулдауны, ограничение одновременных «досугов». При событии работы — прерывание и плавный возврат к месту (ускоренная ходьба).
- Анимации: walk (4 направления), sit, type, read, drink, sleep/doze, talk, hand-raise, appear/leave.
- Расширение офиса: при нехватке мест — авто-расширение сетки/вторая комната (редактор до 64×64 уже есть).
- **Освещение (Canvas 2D, дёшево):** затемняющий слой ночи + аддитивные радиальные «световые пятна» ламп/мониторов, закэшированные в offscreen-canvas; окно с параллакс-силуэтом ночного города и неоном; день/ночь по локальному времени или фиксированная ночь.
- **Арт:** оригинальный арт-пак в формате manifest Pixel Agents (палитра: глубокий фиолетовый, янтарь, неон-циан/маджента, дерево, зелень). Персонажи 16×32, мебель 16×16-кратная. Делаем поэтапно: сначала ключевая сцена, потом расширение каталога.

## 8. UI-концепция

Офис — 100% экрана. Поверх — компактные, скрываемые элементы на тёмных полупрозрачных панелях:

- Верхняя полоса-сводка: обнаружено · работают · ждут · свободны · ошибки; индикатор источников (Claude ✓, Codex ✓, hooks вкл/выкл); бейдж `REPLAY`/`DEMO`, когда включены.
- Правый выдвижной drawer: лента активности (фильтр по агенту/источнику).
- Карточка агента по клику: имя/ID, роль (только из источника, напр. `agent_type`), среда, проект, сессия, статус, текущая задача, последнее действие, время, сабагенты, доступные действия. Закрывается Esc/кликом.
- Управление скрыто в меню карточки/«+». Типографика: пиксельный шрифт только для подписей в мире, UI — чистый sans (с OFL-лицензией).
- Проверка: Impeccable `critique` + `audit` после установки плагина, Playwright-скриншоты.

## 9. Взаимодействие (дополнительно)

- Используем существующее в Pixel Agents: запуск в выбранной папке, PTY-терминал, подключение к своим сессиям; всё — только с токеном, bind `127.0.0.1`.
- **Skip Permissions выключен и спрятан**; никаких автоматических запусков.
- Allow/Deny из офиса (через `PermissionRequest` hook) — этап 4, отдельный тумблер, понятное предупреждение.
- AI-чат — не в MVP; позже опционально, выключен по умолчанию.

## 10. История и Replay

- Журнал `~/.pixel-agent-workspace/history/YYYY-MM-DD.jsonl` (append-only, ротация по дням, лимит по размеру/дням), индекс сессий в памяти. Без нативных зависимостей.
- Вкладка «История»: завершённые сессии, действия конкретного агента.
- Replay: проигрывание сессии в отдельном «историческом» офисе с яркой пометкой; не смешивается с live.
- Demo Mode: синтетические сценарии только явно и с бейджем (нужен для разработки/тестов).

## 11. Производительность и безопасность

- rAF только при видимой вкладке; при отсутствии движения — 15–30 fps; свет и статичные слои кэшируются; батчинг обновлений стора; лимиты ленты/истории.
- Никаких AI-вызовов ради игровой логики; никакого опроса AI.
- Сервер на `127.0.0.1`; токен для управления; маскирование секретов (ключи, токены, `.env`-значения) в tool_input до отправки в браузер и в журнал; установка hooks — только с согласием, бэкапом и кнопкой «удалить».

## 13. MVP и этапы

**Этап 0 — Подготовка** (после одобрения): установка Node 22 LTS (с вашего ОК), импорт Pixel Agents с историей в локальный git, remote `upstream`, ветка `main` + рабочая ветка, `CLAUDE.md`, `NOTICE.md`, сборка и тесты upstream «как есть» на Windows. Установка Superpowers/Impeccable в новой сессии.

**Этап 1 — MVP (Claude Code, реальные данные):**

1. Запуск `npm run start` → браузер; наблюдение всех сессий Claude Code (CLI/IDE/desktop) без запуска через сайт.
2. Модель `ObservedEvent`, расширенные статусы, дедупликация, восстановление WS.
3. Сводка вверху, карточка агента, лента активности.
4. Новая ночная сцена: освещение, окно с городом, кухня, лаундж; оригинальные ключевые ассеты.
5. Досуг персонажей (FSM) в idle/waiting_user; честные подписи статусов.
6. Сабагенты как отдельные персонажи при наличии событий.
7. Журнал истории + просмотр завершённых сессий + Replay (с пометкой).
8. Терминал/запуск из Pixel Agents — скрыт в меню, Skip Permissions выключен.
